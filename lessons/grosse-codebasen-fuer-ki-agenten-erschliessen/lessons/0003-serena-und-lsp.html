Kapitel 03 · Installation, Teil 2

Serena in Pi einrichten

Ein Java-Projekt mit JDTLS indexieren, Serena über MCP anbinden und einen semantischen Treffer erzeugen.

20 MinutenJava/JDTLS validiertread-only Tools

Dein Ergebnis

Pi kann Serena bei Bedarf starten, ein bekanntes Symbol aus deinem lokalen Java-Projekt finden und dessen relativen Pfad als sichtbares Tool-Ergebnis zurückgeben.

Validierungsgrenze

Die Architektur aus Serena, MCP und einem Language Server ist allgemein. Praktisch geprüft wurde hier nur Java mit JDTLS. Verwende für andere von Serena unterstützte Sprachen deren dokumentierten Setup-Pfad und validiere ihn separat.

Laufzeit und Serena installieren

command -v uv git java
java -version

uv tool install -p 3.13 'serena-agent==1.7.0'
command -v serena
serena --version
serena init

Erwartung: serena --version meldet 1.7.0, und Java ist erreichbar.

Dein Java-Projekt indexieren

Wechsle in das Git-Root deines eigenen Java-Repositories:

cd /pfad/zu/deinem/git-repository
git rev-parse --show-toplevel

serena project create --language java .
serena project index .
serena project health-check .

Erwartung: Der Health-Check endet ohne Werkzeugfehler. Serena erzeugt das lokale Verzeichnis .serena/. Ein erfolgreicher Health-Check belegt den Setup-Pfad, nicht die Vollständigkeit jeder späteren Symbolsuche.

for pattern in '.serena/' '.mcp.json'; do
  grep -qxF "$pattern" .git/info/exclude || \
    printf '%s\n' "$pattern" >> .git/info/exclude
done

git status --short

Den MCP-Adapter für Pi installieren

pi install npm:pi-mcp-adapter@2.27.0
pi list

Erwartung: pi-mcp-adapter@2.27.0 erscheint in der Paketliste. MCP transportiert Tool-Beschreibungen, Aufrufe und Ergebnisse; es ist weder Language Server noch Sicherheits-Sandbox.

Projektkonfiguration erzeugen

Der folgende Befehl liest Serena-Pfad und Git-Root direkt vom Rechner und schreibt daraus .mcp.json. So überträgst du keine langen Pfade von Hand.

SERENA_BIN="$(command -v serena)"
PROJECT_ROOT="$(git rev-parse --show-toplevel)"

python3 - "$SERENA_BIN" "$PROJECT_ROOT" <<'PY'
import json
import sys
from pathlib import Path

serena_bin, project_root = sys.argv[1:]
config = {
    "settings": {
        "toolPrefix": "server",
        "scriptMode": False,
        "hostConfigDiscovery": "off",
        "sampling": False,
        "elicitation": False,
        "outputGuard": True,
    },
    "mcpServers": {
        "serena": {
            "command": serena_bin,
            "args": [
                "start-mcp-server",
                "--context", "ide",
                "--project-from-cwd",
                "--open-web-dashboard", "false",
            ],
            "cwd": project_root,
            "lifecycle": "lazy",
            "directTools": [
                "initial_instructions",
                "get_symbols_overview",
                "find_symbol",
                "find_referencing_symbols",
                "find_implementations",
                "get_diagnostics_for_file",
                "search_for_pattern",
            ],
            "debug": False,
        }
    },
}
Path(".mcp.json").write_text(json.dumps(config, indent=2) + "\n")
PY

lifecycle: "lazy" bedeutet: Serena startet erst beim ersten Serena-Aufruf. Die explizite Tool-Auswahl hält mutierende Werkzeuge aus dieser Lernstrecke heraus. Prüfe Konfigurationsdatei und absoluten Pfad, bevor du Pi startest.

Serena erstmals aus Pi aufrufen

Wähle einen Klassennamen, dessen Definition du in deinem Repository sicher kennst. Du brauchst diesen Kontrollwert, um den Tool-Treffer unabhängig zu prüfen.

pi

Prüfe zuerst /mcp. Vor dem ersten Tool-Aufruf darf Serena wegen lazy noch nicht verbunden sein. Ersetze danach BEKANNTES_SYMBOL:

Verwende ausschließlich Serena und verändere keine Dateien.
Rufe zuerst initial_instructions auf. Finde danach BEKANNTES_SYMBOL.
Nenne relativen Dateipfad, Symbolart und Namenspfad. Belege die
Antwort nur mit sichtbaren Serena-Tool-Ergebnissen.
