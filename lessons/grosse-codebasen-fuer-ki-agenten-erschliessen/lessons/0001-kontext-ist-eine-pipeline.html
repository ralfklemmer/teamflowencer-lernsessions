Kapitel 01 · Das Problem und die Lösung

Große Codebasen für KI-Agenten erschließbar machen

Wie dein Agent in einem großen Repository gezielt suchen kann, ohne dass das Context Window zur Ablage für alles wird.

10 Minutenkein Vorwissen nötigallgemeine Architektur

Was sich für dich löst

Nach diesem Tutorial kannst du einem KI-Agenten eine read-only Frage in einer großen oder unbekannten Codebase geben. Der Agent erhält zuerst einen begrenzten Überblick und ruft danach gezielt benötigte Code-Details ab – ohne das gesamte Repository in das Context Window zu laden. Du kannst jeden Übergang an sichtbaren Tool-Ergebnissen prüfen.

Warum ein großes Repository schwierig ist

Ein KI-Agent überblickt eine Codebase nicht dauerhaft wie deine IDE. Das Modell arbeitet mit der Auswahl an Informationen, die in einem konkreten Request in sein Context Window gelangt.

Ohne Übersicht weiß der Agent nicht zuverlässig, wo er beginnen soll. Werden vorsorglich immer mehr Dateien geladen, konkurrieren relevante Symbole mit irrelevanten Details. Ein großes Context Window löst deshalb nicht automatisch die Auswahlfrage.

Die zwei Schlüsselkonzepte

Repo Map: der begrenzte Überblick

Eine Repo Map ist eine kompakte, priorisierte Textübersicht wichtiger Dateien und Code-Symbole. Symbole sind benannte Bausteine wie Klassen, Methoden oder Felder.

Aider extrahiert dafür Definitionen und Referenzen mit sprachspezifischen Tree-sitter-Abfragen, gewichtet ihre Beziehungen und rendert eine Auswahl. Die Map ist weder der vollständige Syntaxbaum noch ein vollständiger Aufrufgraph.

Sie beantwortet: „Welche Bereiche und Symbole sind plausible Einstiegspunkte?“ Sie ist bewusst unvollständig. Ihre Aufgabe ist Vorauswahl, nicht Detailwissen.

Serena + Language Server: gezielte Details

Wenn ein interessanter Bereich bekannt ist, stellt Serena IDE-artige Funktionen als Agentenwerkzeuge bereit: Definitionen finden, Verwendungsstellen auflösen, Implementierungen suchen und Dateistrukturen anzeigen.

Die eigentliche Code-Intelligence liefert ein Language Server. Für Java wurde JDTLS als praktischer Pfad validiert. Die Architektur ist sprachübergreifend, aber jeder weitere Sprachpfad braucht einen passenden, von Serena unterstützten Server und eine eigene Prüfung.

Der Language Server kennt das Projektmodell und kann Symbolbeziehungen präziser auflösen als eine reine Textsuche. Serena macht diese Fähigkeiten für Pi zugänglich; Serena ist selbst kein Sprachmodell.

Deine Daumenregeln

Aider: Repository map · Language Server Protocol · Serena-Dokumentation

Frag nach

  1. Markiere eine relevante Stelle und notiere deine Frage, deinen Einwand oder deinen Praxisfall als Kommentar.
  2. Öffne deinen eigenen KI-Agenten und gib ihm diese Seite als Kontext: Lass ihn die Lesson-Datei lesen oder füge den Seiteninhalt in den Chat ein.
  3. Klicke oben rechts auf „Kopieren“. Dadurch landet die markierte Textstelle samt Kommentar als JSON in der Zwischenablage.
  4. Füge dieses JSON in den Chat deines KI-Agenten ein.
  5. Jetzt könnt ihr gezielt an deiner markierten Frage weiterarbeiten.
