Kapitel 01 · Das Problem und die Lösung

Große Codebasen für KI-Agenten erschließbar machen

Wie dein Agent in einem großen Repository wirksam helfen kann, ohne dass das Context Window zum Flaschenhals wird.

10 Minutenkein Vorwissen nötig

Was sich für dich löst

Nach diesem Tutorial kannst du einem KI-Agenten eine Aufgabe in einer großen oder unbekannten Codebase geben. Der Agent erhält zuerst einen begrenzten Überblick und ruft danach gezielt die benötigten Code-Details ab – ohne das gesamte Repository in das Context Window zu laden. Du kannst außerdem prüfen, ob dieser Zugriff wirklich funktioniert.

Warum ein großes Repository für einen KI-Agenten schwierig ist

Ein KI-Agent kann eine Codebase nicht auf dieselbe Weise dauerhaft überblicken wie deine IDE. Das Modell arbeitet immer mit einer begrenzten Auswahl an Informationen in seinem aktuellen Context Window.

Bei einem großen Repository entstehen deshalb zwei Probleme: Ohne Übersicht weiß der Agent nicht zuverlässig, wo er beginnen soll. Lädt er vorsorglich immer mehr Dateien, konkurrieren relevante Klassen mit einer wachsenden Menge irrelevanter Details.

Das Ziel ist also nicht, möglichst viel Code in den Kontext zu drücken. Das Ziel ist ein kontrollierter Zugriff:

deine fachliche Aufgabe ↓ Repo Map grenzt den globalen Suchraum ein ↓ Serena + Language Server prüfen konkrete Code-Beziehungen ↓ nur die jetzt benötigten Details gelangen zum Agenten ↓ der nächste Schritt wird präziser

Die zwei Schlüsselkonzepte

1 · Repo Map: der begrenzte Überblick

Eine Repo Map ist eine kompakte, priorisierte Übersicht wichtiger Dateien und Code-Symbole. Symbole sind benannte Bausteine wie Klassen, Methoden oder Felder.

In diesem Tutorial erzeugt Aider diese Übersicht aus den Strukturen und Verweisen im Repository. Die Ausgabe hat ein festes Budget. Dadurch bleibt der globale Überblick klein, auch wenn die Codebase deutlich größer wird.

Die Repo Map beantwortet: „Welche Bereiche und Symbole sind plausible Einstiegspunkte für meine Untersuchung?“ Sie ist bewusst unvollständig. Ihre Aufgabe ist Vorauswahl, nicht Detailwissen.

2 · Serena + Language Server: gezielte Details

Sobald ein interessanter Bereich bekannt ist, braucht der Agent präzise Code-Navigation. Serena stellt ihm dafür Funktionen bereit, die du aus einer IDE kennst: Definitionen finden, Verwendungsstellen auflösen, Implementierungen suchen und die Struktur einer Datei anzeigen.

Die eigentliche Code-Intelligence liefert dabei ein Language Server. Welcher Server arbeitet, hängt je nach Programmiersprache vom Projekt ab. Für Java verwendet unser Beispiel JDTLS; andere Sprachen benötigen ihre passende Language-Server-Implementierung.

Der Language Server kennt das Projektmodell und kann gleich benannte Methoden, Typen und echte Symbolbeziehungen auseinanderhalten. Serena macht diese Fähigkeiten als gezielte Werkzeuge für Pi zugänglich. Serena ist selbst kein Sprachmodell.

Woran du das mentale Modell erkennst

Frag nach

  1. Markiere eine relevante Stelle und notiere deine Frage, deinen Einwand oder deinen Praxisfall als Kommentar.
  2. Öffne deinen eigenen KI-Agenten und gib ihm diese Seite als Kontext: Lass ihn die Lesson-Datei lesen oder füge den Seiteninhalt in den Chat ein.
  3. Klicke oben rechts auf „Kopieren“. Dadurch landet die markierte Textstelle samt Kommentar als JSON in der Zwischenablage.
  4. Füge dieses JSON in den Chat deines KI-Agenten ein.
  5. Jetzt könnt ihr gezielt an deiner markierten Frage weiterarbeiten.
