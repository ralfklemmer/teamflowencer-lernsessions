Kapitel 04 · End-to-End-Nachweis

So beweist du, dass es funktioniert

Nicht die Installation zählt, sondern die beobachtbare Wirkung in einer echten Codebase.

15 MinutenTool-EvidenzSkalierungscheck

Dein Ergebnis

Du kannst Verfügbarkeit, Integration und tatsächlichen Nutzen getrennt prüfen und weißt, welche Effekte bei einer größeren Codebase sichtbar werden sollten.

Der vollständige Nachweis

[1] CLIs vorhanden ↓ [2] echter repo_map-Aufruf liefert globale Kandidaten ↓ [3] echter Serena-Aufruf findet ein bekanntes Symbol ↓ [4] Serena löst eine konkrete Referenzfrage ↓ [5] Pi beendet sich sauber; Git bleibt unverändert

Gate 1 · Verfügbarkeit

command -v pi aider serena git
pi --version
aider --version
serena --version

Dieses Gate beweist nur, dass die Programme erreichbar sind. Es beweist noch keine Integration.

Gate 2 · Globale Orientierung

Starte Pi im Git-Root einer Codebase, die groß genug ist, dass du den Einstieg nicht durch kurzes Scrollen vollständig erfassen kannst.

Erzeuge einen echten repo_map-Aufruf mit 2048 Map-Tokens.
Verändere keine Dateien. Nenne fünf sichtbare Einstiegspunkte und
kennzeichne ausdrücklich, welche fachliche Detailfrage offen bleibt.

Bestanden, wenn: Der Tool-Call sichtbar ist, Pfade und Symbole aus deinem Repository stammen und die Ausgabe begrenzt bleibt.

Gate 3 · Gezielte semantische Navigation

Wähle einen der Einstiegspunkte aus der Map. Lass Serena zuerst die Definition und danach ihre Referenzen suchen:

Verwende Serena read-only. Finde das Symbol <SYMBOL_AUS_DER_MAP>.
Lies nur die für seine Rolle nötige Definition. Suche danach die
referenzierenden Symbole. Trenne sichere Treffer von offenen Fragen.

Bestanden, wenn: echte Serena-Tool-Calls sichtbar sind, der Definitionspfad stimmt und mindestens eine Referenz manuell im Code oder in der IDE bestätigt werden kann.

Gate 4 · Der entscheidende Übergang

Jetzt prüfst du nicht nur beide Werkzeuge einzeln, sondern ihr Zusammenspiel:

  1. Die Repo Map liefert einen plausiblen Bereich.
  2. Aus einem Map-Befund entsteht eine konkrete Symbolfrage.
  3. Serena beantwortet genau diese Frage, ohne wahllos viele vollständige Dateien zu laden.
  4. Pi kann danach genauer sagen, was bekannt ist und was noch geprüft werden muss.

Wenn Serena lediglich dasselbe wiederholt wie die Map, war die zweite Frage zu ungenau. Wenn Pi direkt Dateien durchsucht, obwohl eine klare Symbolfrage vorliegt, wurde Serena nicht sinnvoll eingesetzt.

Ein belastbarer Vorher/Nachher-Test

Nimm eine reale Frage, deren Antwort über mehrere Module verteilt ist. Führe sie zweimal in frischen Pi-Sitzungen aus:

  1. Baseline: nur normale Datei- und Textsuche erlauben.
  2. Pipeline: zuerst Repo Map, danach Serena für konkrete Symbole verwenden.
  3. Vergleiche Tool-Calls, geladene vollständige Dateien, falsche Einstiegspunkte und ungeklärte Behauptungen.

Erwarte keine magische Prozentzahl. Der qualitative Gewinn ist erreicht, wenn die zweite Untersuchung früher zu begründeten Symbolfragen kommt, weniger breite Dateilesevorgänge benötigt und ihre Unsicherheiten klarer benennt.

Gate 5 · Sauberer Abschluss

Beende Pi regulär und prüfe anschließend:

ps -axo pid=,ppid=,command= | \
  grep -E '[s]erena start-mcp-server|[o]rg\.eclipse\.equinox\.launcher' || true

git status --short

Bestanden, wenn: keine zur Sitzung gehörenden Serena-/JDTLS-Prozesse übrig bleiben und git status --short keine unerwartete Änderung zeigt.

Wenn ein Gate fehlschlägt

  1. Analyse: konkrete Fehlermeldung und betroffenes Gate benennen.
  2. Hypothese: genau eine plausible Ursache priorisieren.
  3. Nächster Befehl: einen engeren Check ausführen, der nur diese Ursache prüft.

Wiederhole niemals denselben fehlgeschlagenen Aufruf unverändert.

Abschlusscheck

Dann funktioniert dein Setup

Du hast nicht nur drei Programme installiert. Du hast gezeigt, dass Pi eine begrenzte Landkarte erzeugen, daraus eine präzise Frage ableiten und diese mit lokaler Code-Intelligence beantworten kann.

Frag nach

  1. Markiere eine relevante Stelle und notiere deine Frage, deinen Einwand oder deinen Praxisfall als Kommentar.
  2. Öffne deinen eigenen KI-Agenten und gib ihm diese Seite als Kontext: Lass ihn die Lesson-Datei lesen oder füge den Seiteninhalt in den Chat ein.
  3. Klicke oben rechts auf „Kopieren“. Dadurch landet die markierte Textstelle samt Kommentar als JSON in der Zwischenablage.
  4. Füge dieses JSON in den Chat deines KI-Agenten ein.
  5. Jetzt könnt ihr gezielt an deiner markierten Frage weiterarbeiten.
